# PPT 素材整理（Intake）

## 职责边界

只做**结构化**：识别讲了几件事、每件事下有什么、哪些可合并或删减、备注放哪。不设计页面，不美化。

## 第零步：先问任务简报

收到内容后，**不要直接开始分层**。先问三个问题：

1. **这是什么类型的报告？** 工作汇报 / 项目复盘 / 方案提案 / 行业或产品解读 / 数据分析 / 培训课件 / 其他。
2. **大概做几页？** 正文几页、附件几页、要不要封面目录。
3. **给谁看、用来做什么？** 对内决策 / 对外宣讲 / 平级同步 / 存档。

用户不愿回答时，按内容量给一个默认建议并说明理由，再继续。

把答案写在稿子顶部的任务简报里：

```text
◆ 任务简报
    - 类型：产品发布解读
    - 正文：1 页
    - 附件：3 页
    - 受众：内部团队
    - 用途：同步发布会信息
```

任务简报是后续环节的硬约束：`ppt-logic` 按这里的页数定大/小报告，不再按素材量自动升级。

## 思考路径（按顺序执行）

1. **先看讲了几件事**：把材料归纳成若干**板块**（section），每个板块是一件事，不是一句话。
2. **判断逻辑与取舍**：板块之间是什么关系（并列/递进/因果/对比）；哪些可以合并，哪些不重要可以删减。
3. **拆板块内部**：每个板块下写了什么，是否还有下级；把内容拆成 `text` / `data` / `image` 三类基本项，最多三层。
4. **归置备注**：数据来源、口径、补充说明统一放该板块的 `notes`，不混进正文项。
5. **写总述**：用一到两句话总结整个事件最重要的信息，先备着，供后续环节使用。
6. **写 Insight**：每个板块或整体给一条启示，按下面的定义写；写不出就留空并说明原因。

## Insight 定义

Insight 不是复述事实，而是**基于整理的动向信息给出判断**：

1. **首选**：结合我们自己的情况，说明**如何应对**。
2. **次选**：如果很难写应对，就写**这一动向对后续市场、竞品或其他对象的预判影响**。
3. 必须能回指到具体素材；不得编造数据或外部事实。

## 输出格式：项目符号层级稿

默认输出一份项目符号稿，用户可以直接在上面改。符号固定，不得混用：

| 符号 | 含义 | 缩进 |
|---|---|---|
| `◎` | 分页符，一页一个；页数按任务简报 | 0 |
| `■` | 页内一级板块（最大分类，如 技术 / 效果） | 0 |
| `•` | 二级板块（分类） | 4 空格 |
| `-` | 三级条目（具体做法或表现） | 6 空格 |
| `·` | 三级条目下的明细（可选） | 8 空格 |
| `~` | 板块总结，紧跟 `■` 或 `•` 行 | 与所属板块同级 |
| `←` | 效果板块对技术条目的引用 | 行尾 |
| `#M-xxx` | 素材编号 | 行尾 |
| `※` | 附件 | 0 |
| `◇` | 备注 | 0 |
| `→` | Insight（可单独成页，也可作为页内模块） | 0 或对应层级 |
| `{{…}}` | 行尾样式标记，如 `{{15\|#1F4E79\|b}}` = 字号 15 / 颜色 / 加粗 | 行尾 |

示例：

```text
■ 技术
    ~ 昆仑架构由平台、增程、安全三块组成。
    • 昆仑平台
      ~ 三件事把座舱从固定变成可变。
      - 纯平地板
        · 贯穿地板约 2.9 m #M-007
        · 地板角度 2.95° #M-007
      - 超长滑轨
        · 座椅旋转对坐、一键切换大床 #M-008
■ 效果
    • 空间可变
      - 旋转对坐、一键大床 ← #M-007 #M-008
※ 附件
    • N90 Max
      - 预售 29.99 万元 #M-028
◇ 备注
    - 品牌定位：……
◆ 整体 Insight
    - ……
```

需要机器可读时，另存一份 YAML，字段与上面一一对应（`sections` / `items` / `notes` / `insight` / `gaps`）；项目符号稿是主稿，YAML 是派生物。

## 层级约定

1. **`◎` 才是页**：一页可以放多个 `■`，页数按任务简报来定，不按 `■` 数量自动分页。
2. **`■` 是页内一级板块**：例如「正文一页，主要内容分两块：技术、效果」，就写一个 `◎ 第 1 页`，下面两个 `■`。
3. **`•` 是一件事**：二级板块只表达一个主题，下面接 `-` 的具体数据或做法。
4. **`-` 是最小可引用单元**：一条一个数据点或一个做法，能单独加 `#M-xxx`。
5. **越详细越靠下**：上层不重复下层的总结；二级板块名已说明主题时，不再加“包含 A、B、C”的总结。
6. **Insight 个数不固定**：整体一条用 `→`；正文分多个主要板块时，每个板块可以各有一条 `→`。
7. **附件按内容量合并**：附件页内容少（单页不足 5 条）且没有图片、表格时，合并成一页；有图、表格或单页超过 6 条时独立成页。合并后再算总页数，不按素材块数硬拆。
8. **正文一页时**：不配封面；Insight 不单独成页，只作为正文底部一句。正文超过一页时，才考虑封面与独立 Insight 页。

## 执行规则

1. **先分层，再编号**：先定板块，再在板块内给条目编号；条目 ID 全报告唯一，供下游引用。
2. **一板块一件事**：板块标题是“一件事”，不是“一句话”；同一件事的多个数据点放在同一板块内，避免台账碎片化。
3. **可合并就合并**：同一主题的多个点合并成一个条目，用分号或换行区分；目标是一个正文板块对应 5–8 个条目。
4. **可删减就删减**：不影响结论的细节移到 `notes` 或直接删掉，并在确认时说明删了什么。
5. **数字带口径**：`kind: data` 必须填 `caliber`（时间、单位、含税与否等）。
6. **图片单独登记**：`kind: image` 只写图片内容说明和来源，不描述不存在的内容。
7. **AI 扒取默认待核验**：扒取来的条目在 `source` 标注 URL 与时间，并在确认时提示核验。

## 交互协议

1. 产出后直接把项目符号稿展示给用户，并写入工作区 `outline-bullets.md`。
2. 用户**直接在稿子上改**，改完贴回对话或保存文件；后续环节读取文件版本，不再逐条口头确认。
3. 单独列出 `gaps`，问用户补数据还是按缺口处理。
4. 用户说「直接开始」时进入快速模式：只列 `■` / `•` 标题、`~` 总结、`◇` 备注和 `◆` Insight，条目明细可后置。
