# PPT 素材台账（Intake）

## 职责边界

只做三件事：**接收、切分、登记**。不判断论点好坏，不设计页面，不美化。

## 输入

三种入口，可混用：

1. **用户直接粘贴/口述**：一段文字、一组数据、若干要点。
2. **文件导入**：Word / Excel / PDF / 旧 PPT，按段落或表格行切分。
3. **AI 扒取**（仅在用户明确授权联网时）：抓到的内容逐条登记来源 URL 和抓取时间，默认标记为 `待核验`。

## 台账字段

每条素材必须是一个独立条目，字段固定：

| 字段 | 含义 | 必填 |
|---|---|---|
| `id` | 条目编号，格式 `M-001` | 是 |
| `type` | `data` / `fact` / `opinion` / `gap` | 是 |
| `content` | 原文摘录或要点，不改写原意 | 是 |
| `source` | 来源，如「用户提交/Q3数据.xlsx」「网页: URL」 | 是 |
| `caliber` | 口径说明，如「含税，2026Q3」；无则留空 | 否 |
| `gap_note` | `type=gap` 时说明缺什么 | 否 |
| `verified` | `已核验` / `待核验` | 是 |

## 输出格式

```yaml
materials:
  - id: M-001
    type: data
    content: "华东区营收 1.2 亿，同比 +18%"
    source: "用户提交/Q3经营数据.xlsx"
    caliber: "含税，2026Q3"
    verified: 已核验
  - id: M-002
    type: gap
    content: "缺华南区利润率数据"
    source: "用户提交/Q3经营数据.xlsx"
    gap_note: "需要财务补 2026Q3 华南区利润率"
    verified: 待核验
```

## 执行规则

1. **只登记，不补全**：素材里没有的事实不得自行添加；缺数据时登记为 `gap` 条目。
2. **一条一义**：一个条目只表达一个事实或一个数据点，方便后续按 `id` 精确引用。
3. **不改写**：`content` 保留原文关键表述；需要概括时在条目后另起 `summary` 字段，不改 `content`。
4. **数字带口径**：凡涉及数字，`caliber` 必须填写时间、单位、含税与否等口径信息。
5. **AI 扒取默认待核验**：未经用户确认的扒取内容，`verified` 一律为 `待核验`。

## 交互协议

产出完整台账后，**以表格形式展示给用户**，并请求确认：

- 列出全部条目，标注类型和来源。
- 单独列出 `gap` 条目，问用户是补数据还是按缺口处理。
- 用户确认或修改后，才把最终台账交给 `ppt-logic`。
- 用户未确认前，不得进入逻辑框架环节。

## 资源

本 skill 无额外资源文件；台账以对话输出或写入工作区 `materials.yaml` 均可。
